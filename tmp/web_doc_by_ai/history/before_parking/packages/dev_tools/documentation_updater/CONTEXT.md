# Directory Context: `/packages/dev_tools/documentation_updater`

## Purpose
A full npm package with two commands. `pnpm docs:update_by_ai` asks a coding agent to do a full check of the user documentation of the public website against the current rules and code, then leaves the generated files uncommitted. `pnpm docs:judge_by_ai` scores the quality of the generated pages.

## Key Exports & Entry Points
- `src/index.ts`: the public interface for another package. It exports the classes `DocumentationUpdate`, `DocumentationHints`, `DocumentationPrompt`, `DocumentationChecks`, `DocumentationGit`, and `DocumentationPaths`, and their types.
- `src/cli.ts` and `src/judge_cli.ts`: the two command lines, and the executables `documentation_updater` and `documentation_judge` of the `bin` entry in `package.json`.
- `src/documentation_judge.ts`: the class `DocumentationJudge`, which scores the pages with a rubric. `src/documentation_measures.ts` gives the mechanical measures.
- `src/documentation_update.ts`: the class `DocumentationUpdate`, which runs the steps in order.
- `src/documentation_hints.ts`: the class `DocumentationHints`, which collects the hints with no coding agent.
- `src/documentation_checks.ts`: the class `DocumentationChecks`, which tests the generated pages. The Vitest tests also run it on the real repository.
- `src/documentation_paths.ts`: the class `DocumentationPaths`, the only place that knows the paths, the mark, and the source comment.
- `tests/`: the Vitest tests. `tests/test_repository.ts` creates temporary Git repositories, and only the tests import it.
- Commands to run this folder: `pnpm docs:update_by_ai --help` and `pnpm docs:judge_by_ai --help`
- Command to test this folder: `pnpm --filter documentation_updater test`

## Rules
- The shared writer style in `src/documentation_prompt.ts` asks for focused pages, numbered task steps, control locations, expected results or checks, explained terms, consistent names, useful links, and details and solutions supported by the sources.
- Every run has two passes of the coding agent: the outline pass plans the pages and edits no file, then the writing pass writes the pages from the outline. The outline appears in the local report.
- Every generated page has one page type of the Diátaxis framework (`tutorial`, `how-to`, `reference`, `explanation`) in a comment `<!-- page type: ... -->` after the mark, and the sidebar has one group for each type.
- Every page ends with `## Related pages` (2 to 4 links), and a how-to page ends with `## Troubleshooting` (symptom, cause, solution, check) only when the sources show a failure. A source comment may name a code file when a fact comes only from the code.
- A run without `--only` is a full check. The commits since the file `.last_documented_commit` are hints only, and the first run has no hint.
- The source of truth is, in this order: the rules in `docs/agents_rules/user_interface` and the glossary, then the code, then the pull requests and the issues.
- The command writes `.last_documented_commit`, never the coding agent, and it writes the current commit of the start of the run.
- Every Markdown page of the documentation folder has the mark `<!-- generated by docs:update_by_ai -->`, except `shortcuts.md`, which `pnpm docs:shortcuts` generates.
- Every comment `<!-- source: <path> -->` names a file that exists.
- A limited run checks new or changed pages and pages naming the selected rule files, and leaves unrelated existing pages unchanged.
- Existing local changes are allowed; the coding agent preserves changes outside the files allowed by the task.
- Only a merged pull request counts as a hint: a commit whose first line starts with `Merge pull request #`. The command takes the range and the Git commands from `ChangeLogGit` of the package `change_log_generator`.
- Git history is read only; the command and coding agent never stage files, create or switch branches, write commits, push, merge, or create a pull request or merge request, because the developer handles those actions outside this process.
- The writer reuses verified screenshots from `packages/auxiliary/website_public/docs/public/documentation_images` near relevant tasks or controls, with descriptive alternative text, and never invents screenshots or image paths.
- The default coding agent is `codex`. The options `--model` and `--effort` go to the coding agent; without them, it uses its own settings. The option `--only <path...>` limits a run to the features of some rule files, and a limited run never writes `.last_documented_commit`, because the check is not full.
- Only `src/documentation_agent.ts` imports the package `raw_coding_agent_cli`.
- The judge edits no file, and its default coding agent is `claude`, so it differs from the default writer `codex`. Claude defaults are `claude-sonnet-5-5` and `high` effort. `src/documentation_judge_rubric.ts` defines contract version 3. Evidence severity determines scores, checked by `JUDGE_ANSWER_SCHEMA`. Limited evaluations cannot deduct points for unselected pages. Blocking findings prevent acceptance regardless of the average; limitations require review. Compare frozen inputs with the same contract and settings.
