## Style: the pages must be easy to read

- Write for a person using Heidrun. Explain what the person can do or find, without describing how the program works internally.
- Start each page with one sentence that says what the reader can do or find there.
- Keep each page focused on its purpose. For a task, link to a page that explains a prerequisite instead of repeating its instructions.
- Write the steps of a task as a numbered list, with one action in each step.
- Give each step enough information to find the control and complete the action. Describe where a control is or what it looks like when its name alone is not enough to find it.
- Put the result or confirmation next to the action that produces it. Tell the reader how to check that the task worked when a useful check is available.
- Name controls as they appear on screen. Put control names in bold.
- Explain an unfamiliar term in plain words the first time it appears. Use the same name for the same part of Heidrun throughout the page.
- Organize reference information so readers can find and compare entries. Use a table when readers need to look up several controls, choices, actions, or meanings; give each entry a clear name and useful explanation.
- Make links useful for the next step: say what the linked page helps the reader do or find.
- Describe a known problem with its symptom and supported cause and solution. Include a check when the reader can verify that the solution worked.
- Keep pages concise. Include details when they help a reader complete a task, choose an option, understand a result, or recover from a known problem. Do not add defaults, exact dimensions, internal implementation details, or remedies that are not supported by the sources.
- A paragraph has at most three sentences.
