## Style: the pages must be easy to read

The pages are for a person who uses Heidrun, not for a developer. Do not copy or restate the rule files: they are rules for developers, and they hold many details that a user does not need. A page that is one long wall of text is a failure.

- Say what the person can do and how to do it. Do not say how the program works inside.
- Start each page with one sentence that says what the reader gets from it.
- Write the steps of a task as a numbered list, with one action in each step. Write the name of each button, menu item, and window in bold.
- Show a group of buttons or options in a table with two columns: the name and what it does.
- A paragraph has at most three sentences. Never write two paragraphs in a row without a heading, a list, or a table between them.
- Leave out the internal details: where a choice is saved, caches, default values that the person does not need, and rare edge cases.
- Keep each page short. About 30 lines is enough. When you are not sure that a detail helps the person, remove it.
