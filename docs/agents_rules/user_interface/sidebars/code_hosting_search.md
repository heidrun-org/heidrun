## Search and saved searches

The words are defined in [glossary/code_hosting.md](../../glossary/code_hosting.md) ([issue #374](https://github.com/heidrun-org/heidrun/issues/374)).

- Each list has its own search line ([issue #607](https://github.com/heidrun-org/heidrun/issues/607)). The search line is under the title of the list, and holds the search field, then three buttons that show only an icon, at the right of the field, on the same line, in this order: "Search", "Save this search", and "Edit the saved search". The key Enter in the field also runs the search. A search changes only its own list: the other list, its search, and its number do not change. The number of a list is the number found in this list. An empty search shows all the open items of the list. The search of a list stays when the repository changes and after "Refresh". The search line is not shown for a repository without a remote address, and a folded list hides it. A list that finds nothing says "No issue matches the search.", "No pull request matches the search.", or "No merge request matches the search.". While the search of a list runs, this list says "Loading…" under its search line, and the other list stays as it is.
- Immediately after each list title, a circled question mark opens search help. The question mark is smaller than the title text, is separate from the fold button and the search line buttons, and stays visible when the list is folded. The button is an icon button (`btn icon`) of the [shared design rules](../../web_styling/shared_design.md). Opening the help never folds the list, changes the search text, or runs a search. The button has an accessible name that includes the list name. A click, Enter, or Space opens its information card; Escape closes the card. The card follows the hosting service of the selected repository. The first paragraph says to combine filters with spaces, press Enter in the search field to search only the corresponding list, and that without a state filter the list shows open items. The card has no examples, including in the first paragraph. The GitHub card has a separator after this paragraph, then only a link named "GitHub Docs" to [the full search documentation](https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/filtering-and-searching-issues-and-pull-requests). The GitLab card describes the expressions that Heidrun translates, the account represented by `@me`, and unsupported expressions that show an error. Only the merge requests card suggests `is:merged` and `review-requested:@me`.
- On GitHub, the search goes to `gh` as it is, with `--search`, so the whole search language of GitHub works: `author:`, `assignee:`, `mentions:`, `involves:`, `review-requested:`, `label:`, `no:`, the minus sign, `OR`, parentheses, `sort:`, and dates. `gh` adds `is:issue` and `is:pr` by itself, so `review-requested:` finds no issue. A search that names a state (`is:open`, `is:closed`, `is:merged`, or `state:`) is read with `--state all`, so that the search decides. Any other search reads the open items.
- GitLab has no search language, so Heidrun translates the simple words into the filters of GitLab: `author:`, `assignee:`, `milestone:`, `label:` (one label for each word), the minus sign on these four, `no:label`, `no:assignee`, `no:milestone`, `is:open`, `is:closed`, `is:merged`, `review-requested:` (only for merge requests: the list of issues is then empty), `AND`, and the free words. `@me` is the login that `glab api user` gives. For any other word (`mentions:`, `involves:`, `OR`, parentheses, a comma in a label, `sort:`, dates, a quoted phrase, a minus sign on a free word), the list shows "GitLab cannot do this search: <word>" under its search line, and no row. It never ignores a word in silence, because the lists would then show items that do not match the search. The message comes before the call for the login.
- The button "Save this search" of a list is disabled while its search field is empty, and while its text is already the search of a saved search of this list. It opens the window "Save this search", a modal window like the window "Create a custom launcher": the title of the list that the saved search is for, a field "Name" with the focus, the search shown under it, and the buttons "Save" and "Cancel". The key Enter saves, and the key Escape closes the window without a change. "Save" is disabled while the name is empty. A name that already exists in this list keeps the new search under that name, and the window says so. A name that exists in the other list only is a new name. After the save, the new saved search runs in this list.
- Under the search line of a list, a line shows the button "All", then one button for each saved search of this list, in the order of saving. A click on a button fills the search field of this list and runs the search in this list. The button "All" writes `is:issue` in the search field of the list of issues, and `is:pr` in the search field of the list of pull requests, as GitHub reads them ([issue #607](https://github.com/heidrun-org/heidrun/issues/607)). On GitLab, the button "All" writes no search, because GitLab cannot read these words. The button of the search that runs now in this list is filled and pressed, and "All" is filled and pressed when no search runs in this list, or when the search is the one that "All" writes. A list that has no item for this search says "No open issue." and not "No issue matches the search.". The tooltip of a button is its search. A name that does not fit ends with an ellipsis. The line is not shown while the list has no saved search. A separator is under this line, or under the search line when the line of saved searches is not shown, and the rows of the list are under the separator.
- The button "Edit the saved search" of a list is disabled while no saved search runs in this list (when "All" is pressed, or when the search is not saved). Otherwise it opens the window "Edit the saved search" for the saved search that runs in this list: the title of the list, a field "Name", a field "Search", and the buttons "Save", "Cancel", and "Delete". "Save" is disabled, and a message says why, while the name is empty, the search is empty, or the name is the name of another saved search of the same list. After "Save", a saved search that ran still runs, with its new search. "Delete" asks for a confirmation in a dialog that names the saved search, unless the developer unchecks "Ask before deleting a saved search" in the section General of the Settings window (checked by default).
- A saved search is the same in every workspace, and each list has its own saved searches: a saved search of one list never shows in the other list. Heidrun keeps them in the option `codeHostingSavedSearches`, with the other options. The option holds two lists of saved searches, `issues` and `requests`. An entry without a name or without a search as text is dropped when the options load. A saved value that is one single list, from before [issue #607](https://github.com/heidrun-org/heidrun/issues/607), is copied into both lists when the options load, so that nothing is lost.
- Each label in the information card of a row is a button ([issue #607](https://github.com/heidrun-org/heidrun/issues/607)). A click on a label adds the word `label:` with the name of this label at the end of the search field of the list of the row. A name with a space is written between double quotes, for example `label:"Simple Work"`. When the search field already holds this word, a click removes it, and the other words stay. A word with a minus sign, such as `-label:bug`, is another word and stays. The names are compared without the difference between capital letters and small letters. The click then runs the search of this list at once, as the key Enter does, and does not run the search of the other list. The list reloads, so the card of the row closes. The button of a label that the search field holds has `aria-pressed` set to true. The tooltip of the button is "Add this label to the search, or remove it". In the information card of the references line of the Past chats sidebar section, the labels stay plain pills, because that card has no search field.
- The cache of ten minutes has the search in its key, so two searches never share an answer. These calls only read: `gh issue list` and `gh pr list` accept `--search`, and `glab api user` is allowed, and nothing else changes in the allow-list.
