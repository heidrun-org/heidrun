## Search and saved searches

The words are defined in [glossary/code_hosting.md](../../glossary/code_hosting.md) ([issue #374](https://github.com/heidrun-org/heidrun/issues/374)).

- The search field is between the header and the two lists, with one button that shows only an icon: "Search". The key Enter in the field also runs the search. The two lists show the items that match, and the number of each list is the number found. An empty search shows all the open items. The search stays when the repository changes and after "Refresh". The search field is not shown for a repository without a remote address. A list that finds nothing says "No issue matches the search.", "No pull request matches the search.", or "No merge request matches the search.".
- On GitHub, the search goes to `gh` as it is, with `--search`, so the whole search language of GitHub works: `author:`, `assignee:`, `mentions:`, `involves:`, `review-requested:`, `label:`, `no:`, the minus sign, `OR`, parentheses, `sort:`, and dates. `gh` adds `is:issue` and `is:pr` by itself, so `review-requested:` finds no issue. A search that names a state (`is:open`, `is:closed`, `is:merged`, or `state:`) is read with `--state all`, so that the search decides. Any other search reads the open items.
- GitLab has no search language, so Heidrun translates the simple words into the filters of GitLab: `author:`, `assignee:`, `milestone:`, `label:` (one label for each word), the minus sign on these four, `no:label`, `no:assignee`, `no:milestone`, `is:open`, `is:closed`, `is:merged`, `review-requested:` (only for merge requests: the list of issues is then empty), `AND`, and the free words. `@me` is the login that `glab api user` gives. For any other word (`mentions:`, `involves:`, `OR`, parentheses, a comma in a label, `sort:`, dates, a quoted phrase, a minus sign on a free word), the sidebar section shows "GitLab cannot do this search: <word>" and no list. It never ignores a word in silence, because the lists would then show items that do not match the search. The message comes before the call for the login.
- The button "Save this search" is disabled while the search field is empty, and while its text is already the search of a saved search. It opens the window "Save this search", a modal window like the window "Create a custom launcher": a field "Name" with the focus, the search shown under it, and the buttons "Save" and "Cancel". The key Enter saves, and the key Escape closes the window without a change. "Save" is disabled while the name is empty. A name that already exists keeps the new search under that name, and the window says so. After the save, the new saved search runs.
- Under the search field, a line shows the button "All", then one button for each saved search, in the order of saving. A click on a button fills the search field and runs the search. The button of the search that runs now is filled and pressed, and "All" is filled when no search runs. The tooltip of a button is its search. A name that does not fit ends with an ellipsis. The line is not shown while there is no saved search.
- The button "Edit the saved search" is disabled while no saved search runs (when "All" is pressed, or when the search is not saved). Otherwise it opens the window "Edit the saved search" for the saved search that runs: a field "Name", a field "Search", and the buttons "Save", "Cancel", and "Delete". "Save" is disabled, and a message says why, while the name is empty, the search is empty, or the name is the name of another saved search. After "Save", a saved search that ran still runs, with its new search. "Delete" asks for a confirmation in a dialog that names the saved search, unless the developer unchecks "Ask before deleting a saved search" in the section General of the Settings window (checked by default).
- A saved search is the same in every workspace. Heidrun keeps the list in the option `codeHostingSavedSearches`, with the other options. An entry without a name or without a search as text is dropped when the options load.
- The cache of ten minutes has the search in its key, so two searches never share an answer. These calls only read: `gh issue list` and `gh pr list` accept `--search`, and `glab api user` is allowed, and nothing else changes in the allow-list.
