## Workspace

- One workspace is selected at a time.
- The workspace status bar section is the first status bar section, at the left end of the status bar. It shows a status dot and the name of the selected workspace. A click on it opens its information card above the section. The information card does not open when the mouse moves over the section.
- The status dot is always visible, and it sits before the name, in the same place as the dot of a tab. When an agent in another workspace is blocked or has finished, the dot has the color of that status, and it follows the cards of the Needs you sidebar section. Otherwise, the dot shows the status of the selected workspace. A workspace without an agent gets a hollow ring.
- The information card of the workspace status bar section is titled "Workspace" and is 432 pixels wide. It gives the folder, the Git branch, the number of tabs, and the number of agents of the selected workspace. The folder is shown on one line, under the rules of the section "Text that must stay on one line" (in [layout.md](../window/layout.md)): while the pointer is over the information card, a folder that does not fit scrolls sideways to its end, and it shows its beginning again when the pointer leaves. The folder path and Git branch each have a button that copies their value. Under the details, it lists the workspaces. Each workspace shows its name beside the status dot on the left, and its branch in smaller, muted text on the right when it belongs to a Git worktree. A tooltip for a workspace row has the workspace name as its heading, followed by the Git branch and the full folder path. Long paths wrap. The tooltip appears beside the row with an arrow at the bottom left. The rename and close icons appear over the branch on hover without moving the row contents. A click on a workspace selects it, and closes the information card.
- **The order of the workspaces never changes with the status dot or with the presence of an agent.** The list shows the workspaces in the order of Herdr, which is the number of the workspace. A workspace without an agent can sit above a workspace with an agent, and starting, blocking, finishing, or stopping an agent moves no workspace. Only the developer moves a workspace, by drag and drop, with the keyboard, or with the command search. The shortcuts that select a workspace (Command and a digit, Option+Command+Up arrow, and Option+Command+Down arrow) use this same order. The store `session.ts` has one list of workspaces, `workspaces`, and no other list that orders them by agent ([issue 417](https://github.com/heidrun-org/heidrun/issues/417)).
- The list of workspaces has no separator line between the workspaces, and no space between two rows: between the two separator lines, the pointer is always on a workspace. Each row is 32 pixels tall, with the padding inside the row. One separator line sits between the list and the entries "Open workspace from folder" and "Open workspace from this repo worktree" at the end of the information card.
- The line after the workspace status bar section has 6 more pixels of space on each side than the other lines of the status bar, so that the workspace status bar section is not packed against the next status bar section.
- Each workspace of the list offers the rename of the workspace, the close of the workspace, and the move of the workspace by drag and drop. The rename puts a text field in the place of the name in the status bar. A double click on the workspace status bar section does not rename the workspace.
- The entry "Open workspace from folder" asks for a folder, then creates the workspace with the name of the folder and selects it at once, with its first tab and its first pane. Herdr creates this first tab with the workspace, so Heidrun creates no other tab. The pane of this first tab runs the default command of a new tab, the option `newTabCommand` of the settings, the same as a plain click on the plus button of the tab bar ([tabs.md](tabs.md)). With "terminal", the pane is the shell that Herdr started in the folder. With Claude Code, Codex, or Antigravity, Heidrun renames the first tab after the coding agent and starts the coding agent in the first pane ([issue 379](https://github.com/heidrun-org/heidrun/issues/379), [issue 688](https://github.com/heidrun-org/heidrun/issues/688)).
- The entry "Open workspace from this repo worktree" sits after "Open workspace from folder" in the information card. It is disabled when there is no selected workspace or the selected workspace has no repository root. A disabled entry has no hover treatment or title tooltip. The information card uses the normal cursor; only enabled actions use the pointer cursor. The entry opens a centered window titled "Open workspace from the selected repo's worktrees". Reading begins when the developer selects the entry. When the read finishes within half a second, the window opens with the worktrees already shown. Otherwise, it opens in the loading state and shows the worktrees when the read finishes. The window lists every existing worktree of the selected workspace's repository, including the main checkout, and refreshes the list each time it opens or when the developer selects the refresh button in the header. During a refresh, the current rows stay visible until the refreshed list is ready. The rows can be sorted by name, creation time, or latest commit time, in either order. Each row shows a folder icon beside its branch or detached-head name, its folder path, its creation time when available, and the time of its latest commit when available. A separator appears between rows. Selecting a row selects the existing workspace for that folder, or creates and selects a workspace when none exists. A copy button in the top right of each row copies the folder path and shows a check for two seconds after a successful copy ([issue 685](https://github.com/heidrun-org/heidrun/issues/685)).
- The Needs you sidebar section shows the same list of workspaces, in the same order, with the same selection and the same drag and drop, but without the rename and the close ([needs_you_workspaces.md](../sidebars/needs_you_workspaces.md)).
- Two other ways to switch workspace: the command search with ⌘K, and the shortcut Option+Command+Up arrow or Option+Command+Down arrow.
- Heidrun saves the identifier of the selected workspace each time that the selection changes, in the option `selectedWorkspaceId` of the store `settings.ts`. At the next start, Heidrun selects this workspace again, with its last tab and its last pane. When this workspace does not exist any more, Heidrun selects the workspace that Herdr has focused, or the first workspace.
- **No timer reads the snapshot of Herdr** (the workspaces, the tabs, the panes, and the statuses of the agents). The store `session.ts` reads it once at the start, after each event that Herdr pushes (`herdr://event`), after each connection (`herdr://connected`), after each loss of events (`herdr://resync`), and after each action of the developer in Heidrun. Each read gives the page a new list of workspaces, so everything that watches this list by identity runs again. A timer would do this every few seconds for nothing, and the chart of the Statistics window would blink ([issue 616](https://github.com/heidrun-org/heidrun/issues/616)). A timer is not needed as a safety net: Herdr pushes an event for each change of the snapshot that was measured on 17 October 2026 (the creation, the rename, the move, and the close of a workspace, a tab, or a pane, the statuses of the agents, the tokens, and the folder of a pane), and the read after `herdr://connected` and `herdr://resync` covers a lost event. The rename of a pane is the one change with no event: Heidrun reads the snapshot after its own rename, as after every action. The test `session_no_herdr_poll.test.ts` fails when a timer that reads the snapshot comes back. The usage of Codex is the one exception: Codex writes it outside Heidrun, no event announces it, so the page reads it every 10 seconds.
